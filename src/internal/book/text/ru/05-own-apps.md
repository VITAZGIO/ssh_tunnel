# Своё приложение

Кроме приложений из каталога можно поставить своё — сделанное тобой или
кем-то ещё. Это обычная веб-страница (HTML, JS, CSS) и значок, упакованные
в zip. Программ в нём быть не может: архив с exe, dll и подобным программа
не примет.

## Как поставить

1. «Дополнительные приложения» → «+» → **«Из файла»**, выбери архив.
2. Программа покажет, что приложение просит: «видеть устройства сети»,
   «менять правила» и т. п. Согласен — «Установить».
3. Появится плитка с пометкой **«не из каталога»**.

Приложение работает в отдельной песочнице: окна программы и её ключа оно не
видит, а к программе ходит со своим ключом, который пускает только туда, что
ты разрешил. Без разрешения «видеть устройства» оно не получит список
устройств, сколько бы ни пыталось.

Убрать — «…» на плитке → «Убрать». Приложение удаляется целиком, вместе с
его данными.

Из командной строки: `ssh_tunnel.exe apps install app.zip` покажет
разрешения, а с `--yes` — поставит.

## Как сделать

В архиве — `manifest.json`, страница и значок. Пример `manifest.json`:
`{"id": "hello", "name": {"ru": "Привет", "en": "Hello"}, "icon": "icon.svg", "page": "index.html", "permissions": ["state"]}`

Разрешения:

- `state` — видеть, включены ли туннель и сеть устройств;
- `control` — включать и выключать их;
- `devices` — видеть устройства сети;
- `rules` — менять правила (что через сервер, что напрямую);
- `files` — файлы других устройств;
- `traffic` — расход трафика;
- `clipboard` — общий буфер обмена;
- `calendar` — календарь;
- `sitecheck` — проверять сайты.

Ключ приложения — третья часть адреса его страницы:
`const KEY = location.pathname.split('/')[3]`, запрос —
`fetch('/api/state', {headers: {Authorization: 'Bearer ' + KEY}})`.
Свои данные приложение хранит в программе: `/api/app/data`.

Готовый образец и полное описание формата — на GitHub, в
`docs/custom-app-sample` и `docs/CUSTOM_APPS.md`.
