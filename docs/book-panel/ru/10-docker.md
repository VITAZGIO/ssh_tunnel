# Docker-контейнеры

Панель сервера не управляет Docker. Выбор того, как контейнер ходит в интернет,
делается в программе на Linux-машине, где запущен Docker. Здесь описано, что
это значит, чтобы ты понимал, когда на сервере такое есть.

Подробная инструкция — в Книге программы, глава «Docker». Этот текст только
объясняет границы.

## Три выбора

У каждого контейнера три положения:

- **Как компьютер** — по умолчанию. Программа контейнер не трогает: он идёт
  так же, как сама машина.
- **Через сервер** — только через туннель, строго. Если туннель выключен,
  переподключается или программа упала, у контейнера **интернета нет**. Мимо
  туннеля он не уйдёт.
- **Напрямую** — мимо туннеля, через домашнюю сеть, даже когда сама машина
  ходит через сервер.

Соседние контейнеры, домашняя сеть и сеть устройств при любом выборе работают
как прежде.

## Строгий режим «через сервер»

В режиме «через сервер» список «всегда напрямую» к контейнеру не применяется.
DNS-запросы контейнера уходят в туннель, и отвечает на них DNS программы. Так
провайдер их не видит. Без туннеля имена не разрешаются.

## Без VPN — без интернета

Галочка **без VPN — без интернета** есть у контейнера «через сервер». Без неё
выключенный VPN возвращает контейнер к положению «как компьютер». С ней
контейнер остаётся без интернета, даже если VPN выключен или программа не
запущена вовсе. Домашняя сеть и соседние контейнеры остаются доступны.

Снять галочку можно только ею же. Выключение плагина её не снимает.

## Опубликованный порт не работает

Порт, проброшенный на роутере в интернет, у контейнера «через сервер» **не
работает**. Ответ ушёл бы через туннель, а не тем путём, каким пришёл запрос.
Для такого контейнера выбирай «Напрямую» или «Как компьютер».

## Docker 28 и новее

Docker 28 и новее отбрасывает пакеты контейнера ещё до того, как их увидит
программа. Поэтому строгий режим на таком Docker потребовал отдельной цепочки
правил. Она есть в программе, и проверка на стенде это подтвердила. На живой
машине с новым Docker это ручная проверка.

## Ограничения

- **Окно запуска.** Пока программа не поставила правило для нового контейнера,
  проходит до секунды, когда у контейнера нет своего правила. Это принято как
  ограничение.
- **Firewall-backend nftables.** Если Docker использует nftables (его включают
  вручную), программа не может запретить Docker подменять адрес контейнера.
  Строгость «через сервер» тогда слабеет, и список «всегда напрямую» снова
  действует на контейнер. Страница плагина покажет ошибку в строке «Правил в
  ядре».
- **Строгий режим на настоящем ядре** проверен на стенде, но на живом Linux с
  Docker пока не подтверждён.
