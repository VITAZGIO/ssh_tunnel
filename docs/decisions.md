# Журнал решений

Каждый чат дописывает сюда, что решили и почему. Старые записи не правим —
если решение поменялось, пишем новую запись со ссылкой на прежнюю.

## 2026-11-02 — QR и ссылка при создании клиента в панели (п. 16)

- QR и «Скопировать ссылку» — **только при создании** клиента: сервер отдаёт
  их лишь в ответе `/api/clients/create`, `/api/clients/config`
  («Показать настройки») — без них. Показывать для любого типа устройства.
- QR несёт ссылку `sshtunnel://import?v=1&d=…` (`docs/IMPORT_LINK.md`), а не
  JSON: короче (код реже), и камера телефона сразу открывает приложение.
  В ссылке только вход (адрес, порт, пользователь, ключ) и привязка к панели.
- Ссылку читает `share.Parse` — значит, её сразу понимают сканер и буфер на
  Android и «Вставить» на ПК, без второго разборщика. Старые версии
  приложения QR из новой панели не прочитают — нужно обновиться.

## 2026-11-02 — ядро 2.0, этап 1 (релиз v1.9.0)

- **Ядро — `src/internal/core`, одно на все платформы.** Две кнопки
  (`Machine`), одно место применения (`Driver.Apply`), одно решение «куда»
  (`Decide`). Причина: функции писались по 2–3 раза (окно ПК, Android,
  настройки), режимы расползались, после переключений оставалось старое
  состояние, которое лечилось перезагрузкой.
- **Кнопки независимы.** Круглая — только туннель, «Сеть устройств» — только
  своя связь. Четыре режима — сочетания. Нажатие во время «Подключаюсь…» —
  отмена этого подключения. Прежнее «Подключить» включало и сеть устройств,
  «Отключить» гасило обе — больше так нельзя; «Выключено» — `POST /api/state
  {"tunnel":false,"mesh":false}` или `/api/stop`.
- **Режим применяется целиком.** `Apply(режим, гигиена)` получает полный план
  (`core.PlanVPN`): маршруты, DNS, запрет DNS мимо адаптера, маршруты к
  серверу. Повторный `Apply` с тем же режимом — после смены сети, пробуждения,
  смены правил — ставит всё заново.
- **Гигиена переключения** (`core.Transition`): при смене круглой кнопки —
  сброс таблицы fake-IP и DNS-кэша системы, закрытие соединений из адаптера;
  при выключении сети устройств — закрытие её соединений; всегда — пересчёт
  решения для каждого живого соединения и закрытие тех, у которых оно
  изменилось. Так ушла поломка «после выключения обхода сайты продолжают идти
  через сервер» (браузер держал соединения HTTP/2).
- **Устаревший подставной адрес — сразу отказ (RST)**, а не попытка
  соединиться: приложение спрашивает имя заново.
- **Прямые соединения на Windows** — к привязке сокета (`IP_UNICAST_IF`)
  добавлен маршрут к адресу через роутер настоящей сети на время соединения
  (`PinDirect`, как давно сделано для сервера). Причина: с включённой точкой
  доступа и другими фильтрами Windows сверяет ответы с таблицей маршрутов —
  соединения «напрямую» висели в SYN_SENT (ноутбук, 02.11). Маршруты не
  ставятся к локальным сетям и 100.64/10; потолок 2048, живут 2 минуты после
  последнего соединения, при смене сети переставляются.
- **Linux: маршрутов к прямым адресам не ставим**, остаётся `SO_BINDTODEVICE`.
  При строгом `rp_filter=1` (RHEL/Fedora) ответы на прямые соединения может
  отбрасывать ядро — проверить на живой системе, при необходимости сделать
  маршруты, как на Windows.
- **Исключённые программы (NetBird) и fake-IP.** DNS в Windows спрашивает
  системная служба, программу по DNS не узнать. Поэтому исключённая программа
  может прийти на подставной адрес — стек возвращает имя, ядро решает
  «напрямую», прямое соединение разрешает имя через DNS настоящей сети. Для
  UDP то же самое (`tunnel.RouteUDP`, раньше UDP шёл только через
  ретранслятор или отбрасывался) — нужен NetBird/WireGuard.
- **Поток событий — SSE (`/events`), а не WebSocket.** Односторонний поток,
  работает в WebView2, Android WebView и браузере без библиотек; команды идут
  POST-ами. Набросок ТЗ допускал уточнение.
- **API полный и с самоописанием** (`GET /api`), ключ в заголовке
  `Authorization: Bearer`, адрес и ключ — в `api.json` в папке настроек: на
  нём строятся PowerShell, MCP, сторонние программы (просьба владельца).
- **Карта архитектуры — `docs/ARCHITECTURE.md`**, а не `docs/architecture.md`
  из ТЗ: на Windows имена файлов без учёта регистра, два файла столкнулись бы.
- **Android в этом этапе:** ядро Go на телефоне уже общее (решение «куда»,
  DNS, гигиена переключения, UDP напрямую), служба при выключении одной
  кнопки не останавливается. Не сделано: общий HTML-интерфейс в WebView и
  перенос состояния кнопок из Kotlin в ядро — следующий шаг этапа: без
  проверки на телефоне выкатывать новый интерфейс автообновлением опасно.

## 2026-11-02 — ТЗ 2: дополнительные приложения, Книга, отдельные окна

- **Android на общий HTML — в два шага (решил владелец).** Этот PR: общие
  страницы `apps.html` и `book.html` (`src/internal/uiassets`) с мостом
  `SSHTunnelAndroid` (WebView, `WebPageActivity`) — их отдаёт ядро на телефоне
  (`internal/uihost` через `mobile.StartUI`) с тем же API, что на ПК. Новые
  разделы появляются на телефоне без кода под Android. Главный экран и
  настройки на телефоне пока свои: перевод всего API (настройки, серверы,
  выбор приложений, QR, разрешение VPN) — следующим PR, его можно проверить
  только на телефоне.
- **Страницы — в `internal/uiassets`, а не в `webui/assets`:** их встраивает и
  окно ПК (`webui`), и телефон (`uihost`), а `webui` тянет настольную часть.
  Цвета и темы вынесены из `index.html` в `theme.css` — одни на все страницы.
- **Дополнительные приложения — `internal/addons`.** Описание (манифест) одно
  на все платформы, каталог — в коде (`manifest.go`). Список добавленного,
  звёздочки, выключатели, «подсказку видел» — у ядра в `addons.json` в папке
  настроек (своё на каждом устройстве). Модуль ядра приложения
  (`addons.Register`) работает только у активного приложения: добавлено,
  доступно на этом устройстве, фоновое — включено; страница
  `/addons/<id>.html` у неактивного — 404. Образец (`sample`) — только в
  сборке `dev`, в релизе его нет.
- **Иконки — Material Symbols (Apache 2.0), файлы внутри программы**
  (`uiassets/icons`), рисуются маской цветом текста. На Android стрелка
  быстрого доступа — тот же значок векторной картинкой.
- **Книга — Markdown в `docs/book/`, копия для сборки — в
  `src/internal/book/text/`** (`go generate ./internal/book`; тест сверяет).
  `go:embed` не достаёт файлы вне модуля, а Книга должна работать без
  интернета; так же сделано с `udprelay_server.go.txt`. Разметку разбирает
  страница (простой Markdown без библиотек). На ПК листается страницами
  (колонки CSS высотой в страницу, в широком окне — разворот), на телефоне —
  прокрутка.
- **Отдельные окна на Windows — каждое на своём потоке со своим циклом
  сообщений** (`nativeui.OpenWindow`): так они не зависят от главного (оно
  прячется в трей) и закрываются своим крестиком. Место и размер — в
  `windows.json` у окна (не в `addons.json`: в VPN-версии окна открывает
  процесс окна, а список приложений хранит служба). Окно с тем же ключом
  второй раз не открывается — показывается открытое. При неудаче отдельного
  окна старые процессы WebView2 не закрываются (это процессы главного окна).
  В браузере (Linux `-web`) — `window.open`, место помнит браузер
  (`localStorage`): нативного окна у Linux-версии нет.
- **Страницы интерфейса открыты без ключа** (и в `webui`, и в прокси окна
  VPN-версии): это код, а не данные; данные — только через `/api`, `/events`
  и `/addons/` с ключом. Иначе стили и значки (`theme.css`, `icons/*.svg`) не
  грузились бы — браузер не передаёт ключ в адресах стилей.
- **Linux: маршруты к прямым адресам и к серверу через роутер настоящей сети**
  (`vpnlayer/pins_linux.go`), как на Windows (запись выше от 2026-11-02 про
  Linux). Выбран маршрут /32, а не fwmark + `ip rule`: при строгом
  `rp_filter=1` ядро проверяет обратный путь без метки (пока
  `src_valid_mark=0`), и fwmark сам по себе ответы не спасает; маршрут к
  адресу честен и для отправки, и для проверки. У маршрутов метка `proto 94`
  — по ней после аварийного выхода оставшиеся снимаются при запуске. На
  Fedora руками ещё не проверено (CHECKLIST, п. 17).
