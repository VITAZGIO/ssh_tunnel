# Docker

Для каждого контейнера Docker на этой Linux-машине выбираешь, как он ходит в
интернет. Работает в VPN-версии (`sudo ssh_tunnel_vpn_linux`).

## Три выбора

- **Как компьютер** — по умолчанию: программа контейнер не трогает, он идёт
  так же, как сама машина.
- **Через сервер** — только через туннель, строго. Туннель выключен,
  переподключается, идут секунды после «Выключить» или программа упала —
  **интернета у контейнера нет**, мимо он не уйдёт. Список «всегда
  напрямую» и правила по программам к нему не применяются: они для самой
  машины. DNS тоже: запросы контейнера к любому DNS-серверу (и к домашнему
  роутеру) уходят в туннель, там на них отвечает DNS программы — всегда
  через сервер, провайдер их не видит; без туннеля имена не разрешаются.
- **Напрямую** — мимо туннеля, через домашнюю сеть, даже когда сама машина
  ходит через сервер.

При любом выборе остаются как были: домашняя сеть, сама машина, соседние
контейнеры, сеть устройств и порты, опубликованные в домашнюю сеть (`-p`).

**Порт, проброшенный на роутере в интернет**, у контейнера «через сервер»
не работает: ответ ушёл бы в туннель, а не тем путём, каким пришёл запрос.
Страница плагина пишет это у такого контейнера. Для него выбирай
«Напрямую» или «Как компьютер».

## Без VPN — без интернета

Галочка у контейнера «через сервер». Без неё выключенный тобой VPN (обе
кнопки выключены, служба остановлена) возвращает контейнер к «как
компьютер». С ней — у контейнера нет интернета и тогда: и при выключенном
VPN, и когда программа не запущена вовсе. Домашняя сеть и соседние
контейнеры остаются доступны.

Снять — только этой же галочкой (выключение плагина её не снимает).
Пересозданный контейнер получает новый адрес; пока программа не запущена,
новый адрес не закрыт — запусти программу, и правило встанет.

## Проекты compose

Проект можно переключить целиком — кнопками в блоке «Проекты». Выбор
отдельных служб проекта при этом снимается. Выбор хранится по проекту и
службе (у остальных — по имени контейнера), поэтому переживает
`docker compose up --force-recreate`, смену образа и новый адрес.

## Метка

Метка контейнера `ssh_tunnel.route=tunnel` (или `direct`, `host`) сильнее
выбора в программе — удобно держать её прямо в `compose.yaml`:

```yaml
services:
  qbittorrent:
    labels:
      ssh_tunnel.route: tunnel
```

## Что нельзя отделить

- `network_mode: host` — контейнер в сети самой машины, идёт как она.
- `network_mode: "service:…"` / `container:…` — в сети другого контейнера,
  идёт так же, как тот.

## Выключение

Выключил VPN, остановил службу или выключил плагин — правила снимаются, все
контейнеры снова идут как компьютер (кроме отмеченных «без VPN — без
интернета»). Если программа упала, правила остаются
(контейнеры «через сервер» без интернета) до следующего запуска: поднимется
VPN — встанут заново; не поднимется за 2 минуты — снимутся.

## Если не работает

- Docker с `firewall-backend: nftables` (новый, включается вручную):
  программа не может попросить его не подменять адрес контейнера, и строгость
  «через сервер» ослабевает — список «всегда напрямую» снова действует на
  контейнер. Страница плагина покажет ошибку в строке «Правил в ядре».
- В своих сетях Docker (не `bridge`) имена разрешает встроенный DNS Docker.
  Если у самой машины DNS — только `127.0.0.53` (systemd-resolved), Docker
  спрашивает его от имени машины, и такой запрос идёт как у машины. Надёжнее
  задать контейнеру DNS явно (`dns: [1.1.1.1]` в `compose.yaml`) — тогда
  запрос пойдёт через сервер.

Из командной строки: `ssh_tunnel_linux docker` — список,
`ssh_tunnel_linux docker set container=web route=tunnel` — выбор,
`ssh_tunnel_linux docker set container=web strict=true` — «без VPN — без
интернета».
